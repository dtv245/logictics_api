# Driver settlement calculation contracts

Phase 4B uses explicit assignment actual/planned all miles, never legacy/trip/planned fallback. Missing selected input raises MILEAGE_VALIDATION_REQUIRED before any settlement/snapshot is persisted. Snapshot records basis, assignment ID, policy ID/version, quantity/rate, raw/rounded amounts and rounding version.

Phase 4C uses persisted time_entries.total_hours for HOURLY, not legacy Invoice payroll fields. Duration columns have explicit INTERVAL_SECOND JDBC mapping, verified against real PostgreSQL intervals. Zero explicit hours is valid; absent/negative inputs fail validation. Per-load pay uses each distinct eligible load once within calculation. Daily pay uses one unit per date/policy; flat rate uses one unit per pay period with policy effective at period start. Work calculations snapshot source IDs, method, quantity, rate and policy/rounding versions. Each payable line rounds once before aggregation so settlement totals reconcile with lines.

Current calendar dependency: existing audit specifies UTC persistence and LocalDate for periods/policy dates; settlement period boundaries currently use UTC. Region-specific payroll jurisdiction does not silently change historical settlement calendar semantics.

Phase 4D established explicit historical INVOICE_SUBTOTAL; Billing V1 additionally supports versioned PRIMARY_INVOICE_REVENUE and NET_ELIGIBLE_REVENUE as locked in docs/invoice-rating-v1-contract.md. Eligible subtotals reconcile against currency-qualified lines; document purpose determines economic sign. Ratio is in [0,1], tax/quoted freight never enters the numerator. Missing/noneligible invoice raises REVENUE_PAY_VALIDATION_REQUIRED, not zero wages. Revenue sources deduplicate by load and snapshot document IDs/purposes/signs, policy ID/version, basis, eligible subtotal, ratio and raw/rounded result. Historical INVOICE_SUBTOTAL compatibility is explicit, never a default; no legacy purpose backfill.

BILL-DEC-006 locks pre-finalization behavior: revenue drift at approve/lock rejects SETTLEMENT_REVENUE_BASIS_STALE. Accounting explicitly recalculates and repeats approval; new calculation snapshots retain prior history. Post-lock issue atomically appends audited ADJUSTMENT or a legitimate no-pay-impact audit, never modifies original locked settlement/payroll/payslip. Details and verification boundaries: docs/settlement-billing-revenue-consistency.md.

Phase 4E uses only APPROVED driver_pay_amount. Zero, draft/voided and outside-period charges are ineligible; customer_amount is never a fallback. Positive charges require occurred_at and exactly one distinct historical driver from assignments active at that instant (half-open assignment interval). Trip, trip-stop or load-trip evidence is used; no recipient guessing or splitting. Missing/ambiguous attribution raises ACCESSORIAL_PAY_VALIDATION_REQUIRED; another proven recipient is ignored. Snapshot records charge ID/version, approved/occurred timestamps, recipient and supporting assignment IDs. Load-only charges are included when evidence resolves them, and charge ID dedup prevents duplicate pay. The owning accessorial subsystem is unchanged.

Phase 4F is complete. Assignment work date is the earlier actual completion or assignment end, never clamped into the requested period. Unfinished assignments with explicit actual mileage require validation. Previously reserved original financial sources cannot be reused in overlapping periods; historical daily lines lacking a date require validation rather than backfill. Original calculation locks period then driver; review/approve/lock requires a persisted actor and reconciled line/header currencies and amounts. Validation suspends finalization until explicitly resolved and re-reviewed.

At LOCKED, earning/cost-correction lines with load or trip attribution become individual ACTUAL/APPROVED shipment costs using immutable settlement-line IDs. Header net, advances and reimbursements are not operating cost. A multi-load trip stays trip-only; profitability exposes those unallocated inputs and suppresses derived profit until a real allocation policy exists. Company-only lines stay outside shipment_costs.

Locked header/lines and used driver policies are database-protected. Only LOCKED→PAYMENT_SCHEDULED→PAID progresses; no unlock. Adjustments use parent/sequence/request key, reject changed inputs on retry, and require explicit financial line classification. One idempotent reversal per finalized parent reverses individual line classes and source evidence. Source ID links the original line; the full correction reason is preserved without exceeding line lengths. Correction children pass the same reconciliation/review/approval/lock gate. Database partial indexes serialize uniqueness with row locks; no blanket driver/period uniqueness.

V13 is a forward migration. Legacy constraints use NOT VALID to preserve pre-existing rows; new/updated financial rows must satisfy the constraints. No historical amounts or dates are inferred. Production tenant migration histories are not queried or changed. Clean V1–V13 and populated V12→V13 regression are verified on disposable databases.
