# Task 3.1 canonical cost ledger

`POST /api/expenses/{id}/approve` requires ADMIN or ACCOUNTANT. The authenticated email resolves an employee in the current tenant; clients cannot supply an approval actor. Supported review states are PENDING, SUBMITTED and PENDING_APPROVAL. DRAFT, REJECTED and unknown states cannot be approved. Repeating APPROVED preserves the original approval audit. The command accepts no arbitrary amount/status body.

Expense approval and ACTUAL ledger projection commit atomically. A pessimistic expense-row lock serializes both approval retries and legacy `sync-expenses` repair commands. Unique `(source_type, source_id)` is a second database invariant. Approved expenses without load attribution remain company-level expenses: no load is guessed. Load-attributed approved expenses become VERIFIED costs; source approval is the explicit verification policy, not shipment-cost financial approval.

APPROVED, POSTED and VOIDED costs are immutable. Matching retries return the same logical cost; differing amount, currency, category or attribution rejects. System source types cannot be impersonated via manual cost creation. Basis (ESTIMATE/ACCRUAL/ACTUAL) and workflow status remain independent columns on one record, never duplicate records for status changes.

`POST /api/loads/{loadId}/costs/allocate-maintenance?truckMaintenanceCpm=...&currency=...` uses explicit V3 actual miles from unique single-load trips. Missing/zero mileage, shared-trip attribution, missing truck or multiple historical trucks reject rather than using legacy distance/current load truck. Currency is explicit, no default USD. CPM is nonnegative and at most six decimal places.

Caller-supplied CPM is ESTIMATE, not proof of an actual incurred cost. The amount is rounded only at the configured allocation boundary. Allocation locks the load and uses the existing ALLOCATION source record. Snapshots contain trip IDs, historical truck, eligible miles, CPM, currency, rounding-policy version/mode, engine version and resulting amount. Equivalent retry does not add a cost or snapshot. JSONB formatting does not affect retry equality. Changed pre-finalization inputs append a new immutable snapshot; finalized changes reject.

V12 forward-aligns only legacy audit-column names with the canonical JPA names. V1–V11 are not rewritten. Values, defaults, constraints and timestamp types are unchanged. Both old and canonical columns on a table are treated as an ambiguity and migration fails for explicit reconciliation. Rollout requires coordination with any external consumers still querying quoted legacy audit names; no production database was changed during implementation.
